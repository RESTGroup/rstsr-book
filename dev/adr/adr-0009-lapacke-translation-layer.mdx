# ADR 0009 - LAPACKE translation layer: layout taxonomy, workspace protocol, and deliberate divergences

## Context

The BLAS-device backends (`rstsr-blas-traits` + the `crates-device/*`
vendor crates) call Fortran LAPACK through raw FFI. LAPACK is
column-major-only; users hand us tensors in arbitrary layouts; and several
routines need workspace arrays whose size rules vary per routine. The C
ecosystem solved this twice: **LAPACKE** (the reference C interface:
two-tier `xxx`/`xxx_work` API, row-major bridging via transposed copies,
per-routine workspace query/formula policy) and **scipy's** C++ layer
(copy-to-Fortran + one-malloc arena + an `overwrite_*` buffer-reuse fast
path). rstsr needs the same job done in rust — and, since translations are
largely agent-authored, done *deterministically*: the policy must be
explicit enough that different agents converge on the same code.

## Decision

### 1. Input taxonomy: f-prefer pass-through, clone everything else

Each 2-D tensor input is classified as **f-prefer** (its stride structure
admits a column-major interpretation; f-contiguous is the special case with
a contiguous buffer and `ld == nrows`), **c-prefer** (likewise row-major),
or **fully non-contiguous**.

- f-prefer inputs pass **zero-copy** into LAPACK by raw pointer with `ld`
  derived from the strides (`ld` need not equal any dimension).
- All non-f-prefer inputs (c-contig, c-prefer, fully non-contiguous) are
  **cloned** into a fresh F-order buffer.
- Routines that overwrite their input clone-or-consume **regardless of
  contiguity**.

This generalizes LAPACKE's col-major case (stride-derived ld) while keeping
its copy semantics for everything else; fully-non-contiguous support is an
rstsr extension LAPACKE cannot express. The scipy Cholesky uplo-flip
(computing a C-ordered factor via the flipped triangle) was considered and
rejected for uniformity: one bridge shape everywhere is worth more for
deterministic translation than the saved O(N²) copy against O(N³) compute.

### 2. Output order: hybrid

- **Fresh outputs** are allocated in the **device default order** — the
  numpy-compatible rule (numpy linalg outputs are input-order-independent
  and always C-ordered; scipy's are C by default). On row-major devices
  this costs one F→C bridge copy per fresh output.
- **In-place / overwritable outputs** reuse the input buffer and therefore
  its order (scipy `overwrite_*` semantics). This maximally utilizes an
  f-prefer mutable input (e.g. `solve_general`'s `b`): no bridge copy, no
  extra memory, even on a row-major device.
- View-only f-prefer inputs always pass zero-copy regardless of output
  policy.

### 3. Vendor file shape: two tiers, one file, traits unchanged

Mirrors LAPACKE's `lapacke_xxx` / `lapacke_xxx_work` split, with both tiers
in one physical file shared across vendor crates by symlink:

- `pub unsafe fn xxx_work(..) -> blas_int` — the pure FFI thunk (Fortran
  argument order; `lwork = -1` ⇒ LAPACK query semantics). `pub` for
  cross-crate reachability, but internal-purpose; never prelude-exported.
- the `XxxDriverAPI` trait impl — a thin wrapper: query call → allocate →
  compute call, both calls routed through `xxx_work`.
- `driver_xxx` trait signatures stay fixed; workspace ownership and clamps
  live in the builder layer, not the thunk.

### 4. Workspace protocol: LAPACKE-faithful per-routine policy + O(1) hardening

Query (`lwork=-1`) where LAPACKE queries (gesvd, getri, dsysv, syev, sygv;
double query lwork+liwork for syevd/sygvd), documented fixed formulas where
LAPACK exposes no query (gesdd `iwork = MAX(1, 8·min(m,n))` — allocated
*before* the work query; complex gesvd `rwork = MAX(1, 5·min(m,n))`; the
complex gesdd lrwork formula). The gesvd `superb` superdiagonal follows
LAPACKE exactly (`work[i+1]` real / `rwork[i]` complex) and is returned as
the driver's 4th output.

Mandatory hardening, all constant-budget: query with the real col-major
lds; `MAX(1,·)` on formulas; `lwork==0 → 1` clamp; checked integer
conversion of query values; a `nextafter` guard for f32/c64 query values
(the query result travels the f32 mantissa; ≥2²⁴ values truncate low on
integer conversion → undersized buffers). Fudge factors (scipy's 1.01) are
rejected — vendor-specific workarounds are not policy.

### 5. Error mapping

The thunk returns raw LAPACK `info`. The builder maps: `info<0` →
illegal-argument internal-bug error (with argument index); `info>0` →
per-routine semantic message ("SVD did not converge", "matrix is
singular"); allocation and bridge failures → normal rstsr errors. LAPACKE's
`info−1` remap is not adopted (it exists only because LAPACKE inserts
`matrix_layout` as argument 1; rstsr has no such argument), and synthetic
malloc sentinels do not ride the info channel. Vendor disagreement
arbitration: reference LAPACK / OpenBLAS behavior wins.

### 6. Deliberate divergences

- **No NaN/finite pre-check** (numpy precedent — `numpy.linalg` performs
  none). Risk acceptance, not oversight: the LAPACKE nancheck is
  diagnostics + callee-side robustness, not caller memory safety, and the
  callee hazard survives a rust caller (a NaN pivot in `?sptrf/?hptrf`
  reads uninitialized offsets and writes past `ipiv` while leaving
  `INFO=0`; scipy documents "crashes, non-termination" when its check is
  disabled). Future adoption path: a defaulted `driver_xxx` forwarding to
  `driver_adv_xxx(nthreads, nan_check, ..)` trait shape — a separate
  structural task. When implemented, the scan covers only the logical
  matrix through `lda` (uplo triangle for sy/po), mirroring LAPACKE's
  checkers.
- **Zero-size matrices** are synthesized in the builder (identity
  sub-blocks, empty vectors) without calling the driver — LAPACK-faithful
  results, no vendor edge-case exposure.
- **No triangle-only bridge copies** (no `dsy_trans` analog): uniform
  full-matrix bridges; triangle-only is a sanctioned future optimization.
- **Bridge copies use the per-device orderchange infra** with ambient
  threading, matching every other rstsr copy. A dedicated
  multi-threaded-transpose policy is an open flag, deliberately deferred.
- **`lapack` vs `lapacke` impl trees coexist**, mutually exclusive crate
  features: most BLAS vendors ship no LAPACKE, so the raw-Fortran tree is
  primary; the LAPACKE passthrough stays for openblas+mkl. Validation runs
  the driver suite under each config separately (a past cross-path
  discrepancy was traced to a LAPACKE bug, so cross-validation retains
  value). OpenBLAS is the only vendor validated locally and in CI.
- **No batching** at the driver tier (2-D only); n-dim linalg lives at
  higher tiers (faer device).

## Consequences

- A translating agent needs only the companion skill `lapacke-translation`
  (`rstsr-agents/skills/`; decision tables, skeleton, test matrix) plus the
  routine's LAPACKE source; the skill's gap-notice rule (stop and report
  uncovered situations) keeps unattended translations from improvising.
- f-prefer views with derived lds mean vendor libraries see lds they rarely
  encounter elsewhere; the skill's layout test matrix exists precisely to
  pin those paths against the f-contig baseline.
- Without a nancheck, NaN-input pathologies surface as whatever the vendor
  LAPACK does rather than an early clean error; this ADR records why that
  is accepted.
